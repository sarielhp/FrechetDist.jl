FrechetDist.extract_param_inner — Function
extract_param_inner

Takes the sequence of events (i.e., sequence of points along the curve), and outputs a corresponding sequence of real numbers, where the ith number is the distance of the ith point in sequence from the beginning of the curve. Here, distance means the total distance of the subcurve from the start point, to the current point.

FrechetDist.extract_refined_polygon — Function
extract_refined_polygon( poly, s, points_to_add = 1, delta = 0.0 )

Refine edges along which s (the sequence of matching points
along P) is not monotone, so that the returned polygon has
vertices that hopefully force the Frechet morphing computed in
the next iteration to be monotone.

Arguments

poly: the polygon s: Sequence of events along the polygon poly points_to_add: how many points to add between points of non-monotonicity. The default is 1. Having a larger value speeds up the process of getting rid of non-monotonicity, but the polygons grow faster. delta: if positive, edges shorter than delta / 2 are not refined, and an edge of length l gets round(l / delta) points, clamped to 1..3, instead of points_to_add.

Approximates the Frechet distance between a curve (P) and a subcurve (Q). Here, Q vertices are the vertices of P specified by pindices. That is, Q[ i ] = P[ pindices[ i ]].

FrechetDist.add_points_along_seg! — Function
add_points_along_seg!( pout, times, seg, n_mid_points = 1 )

Arguments

seg: t[1], t[2], .... , t[end]

 t[...]: Time stamps for points on the segment (all between 0 and 1)

Details

Add points along seg at time stamps specified by t, and add points in the middle between them (i.e., refining segment). These new points are added to the output polygon pout. times is sorted and deduplicated in place.

Note that one can set nmidpoints to be larger than 1, but it does not seem to be necessary or beneficial in the experiments we did.

Output: Sorted( t[1]/2, t[1], (t[1]+t[2])/2, t[2],...)

FrechetDist.SweepDist_segs_p — Function
SweepDist_segs_p( p_a, p_b, q_a, q_b )

The oriented sweep distance (continuous dynamic time warping) between the oriented segments p_a p_b and q_a q_b: the integral, over the arc length of p_a p_b, of the distance between the point on p_a p_b and the corresponding point (at the same fraction of the way) on q_a q_b.

FrechetDist.max_leash — Function
max_leash

Gets a segment on one polygon s_a s_b, and a chain P[low:hi]. Updates the
min/max estimates from the leash length. The lower bound is simply the distance
to the nearest point on the segment. The max is the result of brute force
monotonization.

FrechetDist.sqrt_quad_integral — Function
sqrt_quad_integral( u1, u2, k )

The integral of sqrt(u^2 + k^2) over u in [u1, u2], for k >= 0 and an interval of width one (u2 - u1 == 1 is used exactly). The antiderivative is (u s + k^2 asinh(u / k)) / 2 with s = sqrt(u^2 + k^2); it is odd, so an interval around 0 adds two positive terms, and an interval on one side is rewritten so that no two nearly equal terms are subtracted.

FrechetDist.PrevMap — Type
PrevMap

The predecessor map of the VE search: event id => id of the event it was reached from. It starts as a Dict, which is cheap when the search explores few events (similar curves), and moves once to a dense array indexed by (i, j, status) when it holds more than limit entries, which is faster and smaller when the search explores most of the 4 np nq events. Only lookups are used, so the representation does not affect results.

FrechetDist.MAX_COORDINATE — Constant

Largest coordinate magnitude accepted: squared distances must not overflow.

source
FrechetDist.MAX_REFINEMENT_ROUNDS — Constant

Largest number of refinement rounds the iterative algorithms (frechet_c_compute, frechet_c_approx, frechet_mono_via_refinement) may run before giving up with an error instead of looping forever. At most 17 rounds were observed in about 10,000 runs. It is a Ref so that tests can lower it.

source
FrechetDist.MAX_VERTICES — Constant

Largest number of vertices: event ids pack a vertex index into 30 bits, and the search forms ids for index n + 1 (one past the last vertex), which must still fit.
