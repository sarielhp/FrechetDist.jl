# Code review of FrechetDist, November 2026

Branch `fix/code-review-2026-11` (not pushed). Every commit passed `tools/check`
(format, JET, ExplicitImports, julia-audit, tests). Each commit was compared with
its parent by `ruby test/snapshots/compare.rb`. Commits whose results differ are
marked `[RESULT-CHANGING]`, and their messages give the differing entries.

## Summary

The library's algorithms are sound. Most defects sit at the numerical edges and
in the bookkeeping around them:

- Distance and sweep primitives used absolute thresholds. These went wrong at
  large or small coordinate scales.
- The reported bounds (`lower_bound`, `ratio`, `sol_value`) were missing or
  not certified.
- Several sentinels, asserts and loops failed on degenerate but valid input.

Seven defects give a wrong answer without raising an error. All seven are fixed and
have regression tests that fail on the old code:

| Defect | Example on the old code |
|---|---|
| Sweep price of segments (`SweepDist_segs_p`, `Morphing_SweepDist_price`) | 0 instead of 2000 for two tracks 100 m apart at UTM coordinates; DomainError on 23 of 40 walks at scale 1e4; up to 100% error at scale 1e-9 |
| `fp_dist_point_segment`, zero snap | distances below 1e-10 of the segment length reported as 0, so `frechet_ve_r_compute_range` and `FEVER_compute_range` returned (0, 0) for curves 0.5 apart |
| `fp_dist_point_segment`, far endpoint | 0.0110 instead of 0.00141 for a point just past the end of a 1e6 segment |
| `SweepDist_lb_compute` | a "lower bound" of 3.162 above a monotone morphing of price 2.916 |
| `frechet_c_approx` bounds | `lower_bound` above the exact distance (91 of 3600 probe calls); `ratio != leash / lower_bound` |
| `frechet_c_compute` bounds | `ratio` 0 on every result; `lower_bound` 0 on most exits |
| `frechet_ve_r_compute_ext` offsets | NaN or negative offsets returned a wrong leash (or 0) |

## Findings and their disposition

IDs follow the reviewers' tables: C = correctness, M = numerical and morphing,
P = performance, Q = quality and API. Every critical, high and medium claim was
reproduced before it was fixed. Some claims did not hold:

- The `TreeVertex` hash contract is not violated. The overrides were dead code
  and were removed.
- `deepcopy` cost is negligible: `EventPoint` is isbits.
- No invalid morphings are produced. There were 0 invalid outputs from 10 producers
  on 900 pairs.
- The DTW zero sentinel cannot misfire in practice (C14). It was fixed anyway
  with the same change as M4.

## How results were verified

- **Bit-identity:** `compare.rb` on all 1474 snapshot entries for every commit.
  `fp_dist_segment_segment` was also checked on 1.9M random and degenerate calls
  (0 mismatches).
- **Sweep price:** 6000 cases at scales 1e-9 to 1e8, with offsets up to 1e6, against
  a 1024-bit BigFloat oracle. The worst relative error is 6.5e-16 (old code: 1.0, with
  112 errors).
- **Bounds:** against the continuous oracle in `test/oracle.jl`, on every
  agreement family in 2D and 3D with 30 seeds. 0 violations.
- **`0c0ddfd` side effect:** the shortcut's `ratio` can now exceed 1, which makes
  `frechet_c_compute` take its re-approximation branch more often. Tested on
  5-20-vertex curves shifted by 1e3 to 1e16 times their length: errors and
  leashes were identical before and after this commit. That probe found the
  far-apart failure fixed in `48bb7d3`.
- **Regression tests:** in `test/test_review.jl`. Each was run on the unfixed code
  first and failed by assertion.

## Changes a user will notice

- Invalid arguments now raise `ArgumentError` naming the function. Before, they
  raised an `AssertionError` or `BoundsError`, or returned a wrong value.
- `frechet_c_compute` now sets `ratio` and `lower_bound`. `frechet_c_approx`
  can report a `ratio` slightly above 1 where it used to claim exactly 1.
- `DTW_d_compute`, `SweepDist_compute` and `SweepDist_lb_compute` return their
  objective in `sol_value`.
- Removed internals: `DistFunction` and its integrals, `DistFunc_verify_integral*`,
  `integral_alpha`, `discrete_frechet_sample`, `ID_tester`, `fp_equal` on points.
  None was exported. `docs/src/low_level.md` was updated.
